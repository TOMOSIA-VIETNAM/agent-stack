# Rails I18n

- Display strings go through `t` in views, decorators, components, helpers and mailers.
  Never hardcode them.
- Pass values by interpolation, never by concatenating translated pieces: word order
  differs between languages.
  ```yaml
  en:
    articles:
      limit_reached: "You can publish up to %{count} articles."
  ```
  `t('articles.limit_reached', count: limit)`
- Plurals use `count:` with `one`/`other` keys (and the other plural keys the language
  needs).
- Do not redefine Rails' default keys (`errors.messages.blank`, `date.month_names`).
  Take default translations from the `rails-i18n` gem; override a default only for the
  one attribute or model that needs another text.
- Model and attribute names come from `activerecord.models.*` and
  `activerecord.attributes.*` (`human_attribute_name`), not from view strings.
- Define date and time formats once, in `date.formats` and `time.formats`, and render
  with `l(value, format: :short)`. No `strftime` in views or decorators.
- In views use lazy lookup, `t('.title')`, so keys follow the template path. Name keys by
  where they are used, not by their text.
- A key whose value contains HTML ends in `_html`; never call `html_safe` on a
  translation.
- Add every new key to every locale the app ships. Raise on missing keys in development
  and test: `config.i18n.raise_on_missing_translations = true`.
- An API whose client owns the wording returns stable error codes, not translated
  sentences.
